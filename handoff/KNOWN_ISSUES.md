- `SchoolSession.public_status()` 只返回缓存。`GET /api/browser/status` 和 `GET /api/state` 也没有重新检测实际页面。
- 用户在可见原生浏览器里手动点击 / 跳转后，页面可能已进入，但缓存 `selection_ready=false` 不会自动变成true。
- 前端 `renderConnection()` 完全依据上述字段显示“已登录，等待进入课程列表”。前端轮询还有活跃条件，闲置时未必持续轮询。

### 要现场确认的原因候选（不是已证明的学校事实）

1. 表头和表体分别在两张表中，例如某些 Element UI 固定表头。
2. 课程列表在 iframe，当前代码只查主页面。
3. 课程用 `role=grid`、虚拟列表、卡片或 tbody 表头而非标准 table/thead。
4. “课程名称”的实际列名或空列表提示不同。
5. 用户实际列表在另一个新标签页，SchoolSession.page未指向它；不能任意把独立课表标签页当成选课列表。
6. 开着旧服务，新文件已替换但运行中的Python未重新加载；先核对 `/api/health` 版本，不清会话。

### 最小修复目标

在用户本地已经正常登录的同一个上下文，检查实际活动选课标签页及其frames，取得能够说明学生 / 学期 / 批次正确的课程信息。将“进入列表”检测与真正提取目录使用同一份页面/响应证据；检测到真实课程行或学校正常返回的对应目录就更新 `selection_ready=true` / `selection_stage=catalog`。空列表只有在明确进入正确批次且有空列表证据时才标 empty，不能把读取失败当零门课程。

状态刷新应覆盖用户在学校窗口手动导航的情况，采用合适的页面导航 / 正常响应事件或节制的只读检测；不要靠反复登录、强制刷新或每次GET建立新浏览器。课程列表无需重新点“开始选课”；两个入口时尊重实际批次选择。

### 验收

- 用户已打开且可见真实课程列表后，助手能及时显示“课程列表已打开”。
- 本地AI说明是何种DOM/响应证据支撑判断，不通过硬编码true修复文案。
- 用户手动进入列表也会同步状态，不需重输密码；正常退出/会话失效不保持假的就绪状态。
- 复用原Profile、BrowserContext和对应页面；不误识别“我的课表”、模拟页或入口说明文字。
- 将实测组件结构做成不含个人信息的本地fixture，补状态回归测试。

## P0-2：学校目录没有自动出现在“选课计划”

用户原话要点：“进入教务系统选课界面后选课计划并没有出现课程，这个需要github里面的clawai来爬取数据，目前云端做不到。”

### 已证实的源码行为

- `POST /api/browser/connect` 和 `/api/browser/login` 调用的是 `import_current_if_known()`，该函数只导入已有课表，不调用目录读取。
- 只有用户点“读取课程目录” / “读取页面”，触发 `POST /api/browser/catalog`，才能把 `school:catalog` 写进SQLite。
- `read_catalog()` 先调用 `connect()`，如果严格列表检测失败，会在读取之前退出。即使课程真实存在，也无法落库。
- 当前只提取主页面当前可见的普通HTML表格。没有对学校目录JSON响应、分离表头、iframe、分页或虚拟列表做适配。
- 前端连接成功也不自动切入学校模式；目录读取/课表导入成功才在相应按钮处理中切换模式。检查模式时不要混淆学校数据与演练。

### 本地接手步骤

1. 先修 P0-1，共用已确认的课程来源，避免再次开发一套同样严格的探测器。
2. 记录用户正常打开当前批次目录时发出的只读网络响应及页面结构。优先被动监听页面原请求；需要正常API读取时使用当前会话，确认其真正认证方式。教务Cookie不等于选课应用sessionStorage令牌，不能凭空构造认证。
3. 确认“clawai”仓库。候选 Crawl4AI 尚未被用户确认；查实际API和许可证，不预先替换现有Playwright。若使用爬取/解析库，保证能共享合法会话或解析现有页面/响应，避免另起未登录临时浏览器。
4. 完成提取和规范化：真实教学班ID、名称、代码、教师、时间所有片段、学期、入口、批次、容量、已选人数、来源及读取时间。
5. 成功进入且读到有效目录后自动保存 `school:catalog`，让学校模式计划页显示；手动读取按钮继续作为刷新入口。若目录仅当前页，应显式标识，不能宣称全目录已经抓到。
6. 做分页/搜索取数前核验页码稳定性、总数、课程标识与去重，按学校页面允许的正常方式有限读取，避免高频全站爬取。
7. 将课程目录读取状态与已有课表同步状态分开显示。读取失败保持上次目录、显示错误和时间；不要用空数组或演练数据覆盖。
8. 切换学校模式时遵守现有“演练执行中不能切换”的限制；目录更新不得错误删除用户仍有效的预选和优先级。用真实稳定身份对齐，不依赖动态人数产生ID。

### 验收

- 本地正常进入一个开放/预览批次，助手学校计划页自动显示该批次真实课程，无需手动导入JSON。
- 至少验证相同课程名、相同教师但不同班/时间不会合并；剩余人数变化不改变ID。
- 明确区分“读到N门/当前页/完整性待核实/更新失败”，不静默等候。
- 课程行的“选课”按钮不被只读采集点击；当前真实提交仍未启用。
- 目录数据持久化；重复刷新复用会话；失败保留旧快照；实际脱敏结构有回归fixture。

## P1：课程时间和当前学期仍未填入真实目录
