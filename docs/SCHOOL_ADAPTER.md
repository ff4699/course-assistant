# 本校适配状态

## 已有实现

- 单进程 `SchoolSession`：异步锁、独占 Profile 文件锁、固定 `launch_persistent_context`、现有页面复用、正常停止时保留状态。
- 使用上下文共享 Cookie 的 `context.request` 检查 `/student/home`；真正的退出链接作为已登录正面证据。
- 学生教务会话失效时尝试学校正常 SSO；确认需要验证码后暂停，让用户手动填写正常登录表单。
- 通过 `/student/for-std/course-select` 进入独立选课应用，让学校正常生成临时令牌。
- 进入应用后定位可见且可用的“开始选课”入口，点击并等待带“课程名称”列的实际课程行或空列表提示；支持同页加载、跳转和 popup。同一列表页复用，禁用按钮 / 无批次 / 多入口明确暂停；到达应用入口不再等同于课程列表已准备好。该动作只进入列表，不点击每行选课按钮。
- 本校开源课表脚本中的学期选择器和 print-data 路径；不使用其他账号的固定学生、学期或批次 ID。
- 单独复用“我的课表”标签页，监听页面正常触发的当前学期 JSON 响应。已知无分页 get-data 完整课程协议和明确 allCourses 列表可补充未排课记录；如只有活动时间表，不宣称课程完整。
- 按教学班 ID 合并全课程记录与上课活动；支持明确周次、单双周和多个片段的保守时间文本解析，无法解析的部分保持未知。页面“全部课程”补充需核对总数和标识。
- 学校学期信息与有效节次时间优先，缺失时采用用户提供的 2026–2027 校历，并在界面说明时刻来源。
- 共享课表同步器默认 60 秒更新；网络失败、登录失效或完整快照变为部分响应时保留旧数据，显示时间与原因。会话失效时暂停并等待人工操作。
- 独立画面读取锁，使登录或课表读取中的真实浏览器画面仍可显示；遮挡密码输入框、不保存画面文件、不通过截图刷新重复登录。
- 对当前页面课程表格按语义列名进行保守读取。没有稳定教学班 ID 的记录只作本地预选，不用于真实提交。
- 学校模式没有启动真实提交的后端路径；服务对已知增删课程请求和未知的选课应用 POST 作拦截。

## 尚未经过本校登录数据验证

1. 两个入口的实际上下文和课程范围。
2. 每批次的预览、开放、关闭状态；客户端倒计时与服务器开放状态的关系。
3. 完整课程数据与教学班 ID，包括多位教师、多时间片段、单双周和未排课课程。
4. 批量人数读取和真实剩余名额口径。
5. 正常选课按钮触发的请求、错误类型、请求编号和结果反馈。
6. 当前学生、当前学期的完整已选记录，是否能以教学班 ID 精确确认；课表延迟与完整性。
7. 选课应用自己的只读认证检查接口。学生教务登录有效不能单独证明其临时令牌仍有效。

在这些点确认之前，`capabilities.live_submit` 保持 false。源码中没有伪造的 CUPK 提交接口。

本轮对规范化、失败保留、重复同步与界面进行本地模拟验证，未用学生账号确认学校当前的 HTML / JSON 是否仍与适配吻合。不能把本地测试通过等同于已抓到当前账号的全部课程。

## 后续连接执行器的契约

适配器应提供两项能力：

```python
async def snapshot() -> Snapshot:
    # 同一学生、学期、入口、批次的教学班目录和最新人数。
    # page_selected 与 timetable_selected 只能放已精确匹配的目标记录 ID。
    ...

async def submit(course: Course) -> Submission:
    # 顺序执行正常页面支持的选课操作。
    # accepted / unknown / retryable / full / blocked 必须由实际反馈区分。
    ...
```

真实适配器要自行保证 Snapshot 上下文一致、目录完整及身份精确，不能用同名课程或片段文字作为“已选成功”依据。执行器只接收正常页面确定成功的记录；提交超时只产生 unknown，先共享核验，不能直接重发。

UI 应允许先选择实际批次。学校没有开放、发生人工验证或批次关闭时，应暂停；不要用客户端时间、假的服务器响应或学校不支持的批量并发操作绕过这些条件。
