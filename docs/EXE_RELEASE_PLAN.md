# Windows EXE 打包与首次使用流程

日期：2026-10-13。用户已批准协议，本方案在v0.4.0实施；实际交付与验证见WINDOWS_INSTALL.md、SEAT_MONITOR.md及dist的发行/验证清单。下面的步骤保留原先审核顺序，其中原“待确认”事项已由正式协议和根MIT LICENSE落实。

## 交付形式

推荐交付一个安装文件 `CUPK-Course-Assistant-Setup-<version>-x64.exe`，安装后提供桌面快捷方式和应用 EXE。先面向 Windows 10/11 x64 验证，不将未经验证的其他系统列为支持范围。

采用 PyInstaller 文件夹模式收集程序、Python 运行环境和依赖，再由 Inno Setup 制作安装 EXE。匹配 Playwright 的完整 Chromium 浏览器目录随安装包一起提供，无需用户自行安装 Python 或谷歌浏览器。Chromium 为开源浏览器，不宣称是 Google Chrome。当前本地网页界面保留，启动时使用内置浏览器显示。

安装文件是单个 EXE，安装后的程序包含必要支持文件和浏览器目录，不能只复制其中的应用 EXE。这样的布局避免每次启动重新解压完整浏览器。

内置浏览器使安装包较大，最终体积在实际构建后给出。所谓“内置/离线安装”只表示运行依赖随包提供，学校登录和课程读取仍需联网。

## 开发与发布步骤

1. 用户审核 `USER_AGREEMENT_DRAFT.md`，通过后生成 `USER_AGREEMENT.md`。自有代码采用根MIT LICENSE；第三方声明和独立素材权利保留。
2. 实现首次启动协议门禁、默认不勾选、拒绝退出、版本和同意时间的本地记录，以及关于中的协议入口。协议确认前不启动学校登录浏览器、不读取用户课程。协议更新按版本重新确认。
3. 准备专用 EXE 入口，区分安装文件与可写用户数据，默认将新安装用户的数据放在其 Windows 本地应用数据目录。正常退出保存状态，重复启动复用现有服务。现有开发实例的 `.state`、BrowserContext 和用户计划保持原样，不塞进发布包。
4. 核验拟发布内置浏览器的密码保存及自动填充策略，禁用密码保存提示；检查登录表单、错误处理、日志、数据库、导出和发布文件没有密码或令牌泄露。保留会话的行为与协议一致。
5. 收集 Python、网页静态文件、依赖、完整匹配版本的 Chromium、许可证与说明文件；生成应用 EXE，再生成安装程序、快捷方式和卸载项。默认按当前 Windows 用户安装，不要求为日常使用提权。
6. 测试无 Python/无系统 Chrome 的部署场景，检查拒绝与同意流程、主题、课程界面、演练、重启保留状态、中文路径、升级与卸载。能在隔离环境实测的结果单独记录；缺少干净机器验证时明确说明验证边界，不宣称完成。
7. 检查最终安装包只含公开文件，排除开发 `.state`、Profile、数据库、Cookie、认证令牌、日志和个人截图。交付安装 EXE、SHA256、源码包、安装说明及验证报告。

真实学校提交保持未启用，打包不改变其功能状态。安装与协议测试使用虚构数据和独立测试目录，不干扰当前正常登录的学校上下文。

## 新用户操作

1. 获取官方安装 EXE，双击安装，选择安装位置并创建快捷方式。
2. 从快捷方式启动，阅读协议；同意后进入界面，不同意则退出。
3. 正常登录学校，人工完成验证码；依次导入课表、读取课程、选择计划并检查冲突。
4. 核对结果页及学校实际记录；当前真实提交未启用，可以使用本地规划和模拟演练。
5. 后续启动保留计划及可用会话；学校会话过期时正常重新登录。卸载与清理个人数据分开选择。

你无需手动运行打包命令。协议确认后由开发方执行构建和验证，你只需先审核协议，再试用交付的安装程序。
